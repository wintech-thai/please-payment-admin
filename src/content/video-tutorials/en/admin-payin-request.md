# Pay-In Request

This video walks through the **Pay-In Request** page on the Admin side, used to view and manage Pay-In requests across every merchant in the organization in one place.

By the end, you'll be able to create and approve Pay-In requests on a merchant's behalf — useful for admins or support staff who need to generate a payment request or review transactions for a merchant directly.

## What this video covers

- **Creating a new Pay-In request** via the QR Payment dialog — merchant, bank account (chosen manually or auto-selected by the system), amount, payer name, REF 1/REF 2 — generates a PromptPay QR code automatically
- **Generating a Slip Upload Link/QR** so the payer can attach proof of payment
- **Viewing the list of Pay-In requests** with columns for REF, merchant, amount, destination bank account, payer name, and status (Pending/Identified/Approved/Rejected), with search and date-range/status filters
- **Manually approving or rejecting a request** via the Confirm Approve dialog, which summarizes the merchant, account, amount, and REF, and lets you add a remark before confirming
- **Viewing each bank account's transaction summary and wallet balance** — a transaction history table showing Pay-In/Pay-Out entries with +/- amounts and the running balance after each one
